## F) Interview Preparation

**Master Stories to Prepare:**

1. **SDUI Platform Architecture — Node-Based Navigation Framework**
   - S: Inheriting RSA frontend with hardcoded question flows, garden-to-gate onboarding fragile
   - T: Adding new features required frontend deploys, blocked product iteration, tight coupling between product flow and code
   - A: Designed SDUI (server-driven UI) with node-based navigation engine — each question/screen is a configurable node, backend owns flow logic, frontend renders config
   - R: Shipped RSA, PUD, Claims using shared framework; product shipped 5 features without frontend deploys; team velocity increased 3x; pattern adopted company-wide as shared primitive
   - **Reflection:** Realized *inversion of control (flow in config, rendering in code) scales team autonomy* — backend product owners shipped independently, frontend unblocked for optimization.

2. **DevOps Leadership — 60% → 97%+ Test Coverage**
   - S: Inheriting cost dashboard (critical procurement system) with 60% test coverage, frequent production issues, slow deployment cadence
   - T: Manual testing bottleneck, PCF vulnerabilities accumulating, on-call pager fatigue
   - A: Led systematic test coverage drive (unit → integration → E2E), automated CI/CD pipeline, established code review checklist for test requirements, mentored team on testing discipline
   - R: Achieved 97%+, zero critical vulnerabilities, deployment confidence high (Friday ships), team morale improved
   - **Reflection:** *Test coverage is an organizational multiplier* — enabled faster shipping, lower stress, better retention. Infrastructure investment pays compounding returns.

3. **Microservices Boundary Design — Cost Dashboard Architecture**
   - S: Monolithic procurement backend, slow iteration, scaling bottleneck
   - T: Adding new endpoints blocked by monolith deployment cycle, data dependencies scattered
   - A: Designed Spring Boot microservices decomposition — separate approval engine, pricing service, audit trail service; defined API contracts, async messaging for data consistency
   - R: Services independently deployable, pricing team shipped features without approval team involvement, cost dashboard $65M ROI achieved in first year
   - **Reflection:** *Good API contracts = team autonomy* — architecture is team organization made visible. Services aligned with team ownership.

4. **Scale & Reliability — 1000+ Garage Network, Real-Time Tracking**
   - S: PUD platform, garage selection naive, slot-booking unreliable under load
   - T: Slot conflicts, garage unavailability errors, user complaints at scale
   - A: Designed configurable garage-selection logic (bias rules, ADSC vs non-ADSC), built real-time status polling with exponential backoff, implemented conflict resolution (async reservations with idempotency keys)
   - R: 1000+ garages live, 99.5%+ availability, zero user-facing conflicts, live tracking accurate
   - **Reflection:** *Scale exposes architectural gaps early* — good foundational choices (idempotency, async, config-driven logic) compound at 1000x load.
