## F) Interview Preparation

**Master Stories to Prepare:**

1. **RSA Platform — Angular SDUI Architecture +91% Registrations**
   - S: Owned complete RSA frontend (question engine, slot booking, Google Maps location, garage selection, custodian flow, review screen, live tracking)
   - T: Registration rate stalled at 18%, time-to-completion 12 min, user friction high in flow
   - A: Architected SDUI config-driven UI using server-driven patterns; abstracted slot booking, garage selection into reusable components; Google Maps + Segment analytics integration
   - R: Registrations 18%→34.5% (+91%), time 12min→6min (−50%), journey completion 43–47%, support calls 350→200 (−43%)
   - **Reflection:** Realized *configuration over hardcoding reduces deploy friction* — moved dynamic rules to backend, frontend became lightweight config consumer. Shipped faster, iterated quicker.

2. **PUD (Pickup & Drop) — Full-Stack Integration, 1000+ Garages**
   - S: Built garage-selection SDUI with dynamic bias (ADSC vs non-ADSC), real-time slot booking, pricing-by-pincode
   - T: Garage logic scattered across multiple places, pricing rules inconsistent, team unable to ship independently
   - A: Created node-based SDUI navigation (reusable across RSA), data-enricher pattern for pricing/bias logic; designed API contracts with backend team for garage steerability
   - R: 1000+ garages live, zero logic duplication, team velocity increased (independent shipping)
   - **Reflection:** Learned that *good API contracts enable team independence* — invested time in contract clarity upfront, unblocked parallel development.

3. **Code Quality & Team Impact — Cross-team API Reviews**
   - S: Inherited RSA + PUD with inconsistent API patterns, no shared contracts across teams
   - T: Duplicated logic, integration friction, junior engineers confused on API usage
   - A: Led API contract definition meetings, documented patterns, conducted code reviews with junior mentorship focus
   - R: Clear API contracts adopted across RSA, PUD, Claims; juniors independently shipping features within 1 sprint
   - **Reflection:** Realized *culture > process* — junior engineers thrived when clarity and expectations were explicit upfront. Mentorship at scale requires systems, not just 1-1s.

4. **Production Reliability & Operational Excellence**
   - S: RSA/PUD features launched with 60% test coverage, occasional production issues
   - T: On-call pager alerts for UI bugs, integration failures, occasional data inconsistencies
   - A: Increased unit test coverage (Jasmine), added integration tests for API flows, established code review checklist
   - R: Production issues dropped 70%, confident to ship on Fridays, zero critical incidents in 6 months
   - **Reflection:** *High test coverage is a team force multiplier* — enables confidence, fast shipping, low stress. Worth the upfront time.
