| # | JD Requirement | Story | S | T | A | R | Reflection |
|---|----------------|-------|---|---|---|---|------------|
| 1 | Checkout / subscription flow UX | RSA slot booking + payment eligibility at Acko | No structured multi-step user journey for RSA; raw form-based flow with high drop-off | Build dynamic, config-driven journey from browsing → slot selection → eligibility check → confirmation | SDUI question engine, real-time slot polling, payment eligibility gating, Segment funnel analytics | Registration time -50% (12 min → 6 min), support calls -43%, journey completion 43-47% | The bottleneck in checkout-style flows isn't the final step -- it's friction in the middle steps. Segment funnel data proved this. |
| 2 | Config-driven UI rendering (backend-driven) | SDUI architecture at Acko | RSA and PUD product teams kept adding flow variants that required frontend code changes | Design SDUI schema-driven React architecture: flow, components, and pricing rules defined in config | Question engine reads YAML/JSON schema; new flow variants ship via schema updates, not code; slot booking and garage selection both config-driven | New product flows added in 1-2 days instead of 2-3 sprints; patterns adopted across RSA and PUD | If the backend schema isn't versioned, config-driven UI becomes a migration nightmare -- learned this on RSA v2 and built schema versioning as a result |
| 3 | A/B testing / pricing experiments | Growthbook at Acko | RSA had no way to test pricing copy or registration funnel variants without full deploys | Instrument Growthbook feature flags across RSA, PUD, CES, and Claims | Cohort-level rollouts, staged flag activation, flag-gated UI variants | Data from Growthbook rollouts drove the funnel optimisations that produced +91% registration rate | A/B testing is only as good as the metric you pick -- we initially picked registrations but the signal was completion rate; switching the target metric doubled the actionable insights |
| 4 | Internal admin tools for ops/finance | Advisor Portal at Acko | Claims handlers and RSA ops teams had no unified tool to manage bookings and field executives | Build Advisor Portal -- internal ops tool with booking management, field exec live tracking, and status workflows | React + live Maps integration, job status management, SLA tracking -- same codebase as customer-facing RSA but separate permission layer | Adopted by full ops team; eliminated the need for manual status updates via phone | Internal tools have the same UX quality bar as consumer tools -- ops teams spend 8 hours/day in them; investing in them pays off disproportionately |
