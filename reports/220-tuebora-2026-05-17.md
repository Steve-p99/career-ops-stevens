## F) Interview Preparation

**Master Stories to Prepare:**

1. **RSA Platform — React SDUI + Component Architecture +91% Registrations**
   - S: Owned complete RSA frontend (question engine, slot booking, location handling, garage selection, custodian flow, tracking)
   - T: Registration rate plateau at 18%, user friction high, long onboarding (12 min)
   - A: Architected SDUI (server-driven UI with React) — question flows in backend config, frontend renders dynamic components; built reusable slot-booking, garage-selection, location components; integrated Google Maps + Segment analytics
   - R: Registrations 18%→34.5% (+91%), time 12min→6min, support calls 350→200, CES 90%+
   - **Reflection:** Learned that *component abstraction at the right granularity unlocks product velocity* — each component mapped to a product decision, enabling independent iteration without frontend code changes.

2. **PUD — State Management & Real-Time Data Handling**
   - S: Building garage-selection UI with complex state (bias rules, real-time availability, slot pricing)
   - T: State scattered across Redux + local component state, inconsistent data flow, debugging difficult
   - A: Centralized state management (Redux + selectors), designed single source of truth for garage/slot/pricing data; implemented optimistic updates with conflict resolution
   - R: 1000+ garages live, zero data inconsistencies, fast UI response (optimistic updates), team able to understand data flow
   - **Reflection:** *Redux discipline pays off at scale* — centralized state + selectors + middleware patterns enabled confident full-stack feature ownership.

3. **Claims Real-Time Tracking — Performance Optimization**
   - S: Built Claims Timeline UI with history of 50+ events, real-time status polling, SLA timeline visualization
   - T: Initial implementation re-rendered entire timeline on each status update, noticeable lag for users
   - A: Implemented React.memo, useMemo for timeline items; virtualized long lists (window-based rendering); optimized polling with exponential backoff; lazy-load historical sections
   - R: 60+ event timelines render in <200ms, zero perceptible lag, users see live updates without jank
   - **Reflection:** *Performance is a feature, not an afterthought* — React performance optimization (memoization, virtualization) directly enables user experience quality.

4. **Design Systems & Scalability — Component Library Adoption**
   - S: RSA, PUD, Claims each with custom Button, Input, Modal components — inconsistency, maintenance nightmare
   - T: Design changes required updates across 3 codebases, inconsistent UX
   - A: Extracted design system (Tailwind CSS + Material UI base components), published shared library with docs; migrated RSA/PUD/Claims to use shared system
   - R: New features ship 2x faster (reuse components), design consistency high, maintenance centralized, team adopts shared language
   - **Reflection:** *Design systems enable team scaling* — shared components + clear contracts allow parallel feature development without coordination overhead.
